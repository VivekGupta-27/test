Design the UI-only frontend for a web application called WorkDNA, using the shared UI images as the primary reference for visual style, layout, spacing, typography, and information hierarchy. This task is strictly limited to design and frontend implementation only. Do not include any backend logic, APIs, authentication, databases, or real data fetching. All data should be mocked, static, or locally simulated for display purposes.

Build the UI using React or Next.js with TypeScript and Tailwind CSS, with a clean, modular component structure. Use Recharts or Chart.js to render charts and visualizations. The interface should be fully navigable, responsive, and visually complete, closely matching the intent and structure shown in the shared images, while maintaining a calm, neutral, and trust-focused aesthetic.

Implement the following screens based on the shared designs: Dashboard, Add Task, Insights, History, and Settings. The Dashboard should include a welcome header, a “Today’s workload” progress bar based on an 8-hour baseline, a burnout risk indicator (Low, Medium, High), a prominent key insight card with explanatory text, summary cards for completed tasks, tasks due today, overdue tasks, and high-effort tasks, a list of today’s tasks, and a single primary Add Task button.

The Add Task screen should include inputs for task title, date, estimated duration, effort level (1–5), and an optional deadline, along with a non-blocking informational message explaining how the task may affect workload. The Insights screen should display a weekly workload trend chart, an effort distribution chart, and short explainable insight text describing behavioral patterns and changes. The History and Settings screens should follow the structure and tone implied by the shared UI images, with appropriate placeholders for future functionality.

Apply the following UX constraints throughout the design: no gamification, no streaks or rewards, no urgency or pressure cues, and no competitive productivity elements. Prioritize clarity, readability, and insight-driven explanations over raw numerical density. Use consistent spacing, subtle color usage, and restrained typography aligned with the shared UI designs.

Deliver a clean, well-organized frontend codebase with reusable components, mock data models, basic client-side navigation, and clear separation between pages, components, and styles. Include placeholder copy where dynamic or AI-generated insights would appear in future versions.
